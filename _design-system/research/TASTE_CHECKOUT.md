# Payment / Checkout Screen Design — Delta Findings

Delta only. Does not restate Gestalt, Fitts, Hick, pop-out, WCAG/APCA contrast, modular scales, 45-75ch measure, 8pt grids, optical alignment, corner curvature, motion thresholds, or aesthetic-usability/MAYA — already in RATIONALE.md.

## Findings (ordered by usefulness)

1. **Cost surprises are the single biggest abandonment driver.** 39% of users abandon because of unexpected extra charges (tax/shipping revealed late); 14% abandon because they can't see the total cost before starting checkout. Rule: surface full cost (tax, shipping, fees) in the **cart**, before the checkout flow even begins, not first at review. [source: https://baymard.com/learn/checkout-flow-ux-optimization] T2
2. **The review/confirm step must only restate known facts.** Introducing a new fee or shipping cost at review "destroys user trust" — anything not already shown earlier cannot appear for the first time on the final screen. [source: https://baymard.com/learn/checkout-flow-ux-optimization] T2
3. **Primary CTA copy must be action-specific, never generic.** Replace "Continue" with "Continue to Payment"; the final-commit button reads "Place Order" or "Pay & Place Order," and updates dynamically for third-party redirects ("Continue to PayPal") so the user always knows what tapping the button actually does. [source: https://baymard.com/learn/checkout-flow-ux-optimization] T2
4. **Payment fields need visual encapsulation, not just encryption.** Users judge security by whether the card-entry section is visually set apart (border/background/shading) from the rest of the form — perceived trust is a layout property, independent of actual TLS. [source: https://baymard.com/blog/perceived-security-of-payment-form] T2
5. **Trust badges belong 1–2 max, directly inside the encapsulated payment block**, adjacent to the card fields — not in the footer, not scattered. Security concern is concentrated specifically at the card-number field; address/shipping fields don't trigger it. [source: https://baymard.com/blog/perceived-security-of-payment-form] T2
6. **19% of checkout abandonment is explicit distrust of the site with card info** (2025 data, n=1,026); layout bugs/visual glitches near payment can make users suspect the site was hacked, even for known brands. [source: https://baymard.com/blog/perceived-security-of-payment-form] T2
7. **Single-column beats multi-column for forms.** Multi-column layouts create ambiguity about field sequence and confuse keyboard/screen-reader tab order — this is the NN/g "Structure" principle for cognitive load, converging with Baymard's field-grouping guidance below. [source: https://www.nngroup.com/articles/4-principles-reduce-cognitive-load/] T1 (two independent orgs converge)
8. **Field grouping recipe for checkout specifically:** contact + shipping address consolidated into one group; billing defaulted to "same as shipping" (checkbox pre-checked ON); Address Line 2 hidden behind a link rather than shown by default; payment method selection shows only the fields relevant to the selected method. [source: https://baymard.com/learn/checkout-flow-ux-optimization] T2
9. **Errors must be inline, adjacent, and specific — never generic.** "ZIP code is too short" beats "Invalid input." Baymard found 98% of sites tested still use non-specific error language. For multi-error submissions: a summary at the top of the page PLUS inline markers at each field, with auto-scroll to the first error. Never clear the user's already-entered data on a validation failure. [source: https://baymard.com/learn/checkout-flow-ux-optimization] T2
10. **NN/g's "Support" principle matches independently:** error messages adjacent to the problem field, constructive (not just "wrong"), and validation should not fire prematurely mid-typing. [source: https://www.nngroup.com/articles/4-principles-reduce-cognitive-load/] T1 (converges with #9)
11. **Field-count benchmark:** average ecommerce checkout carried 12.8 form fields as of 2019 (down from 14.88 in 2016); an optimized guest-checkout flow can run 6–8 fields including card entry. [source: https://baymard.com/blog/checkout-optimization-from-16-fields-to-8] T2
12. **Named abandonment drivers, ranked:** unexpected extra charges 39%; forced account creation / hidden guest path ~18-19%; process felt too long/complex 18%; preferred payment method unavailable 10%. These are the concrete "checkout failure patterns" to diagnose against. [source: https://baymard.com/learn/checkout-flow-ux-optimization] T2
13. **Mandatory field-required/optional transparency:** mark required vs optional explicitly (asterisk + literal "(optional)" text) and state field-length expectations before the user starts. [source: https://www.nngroup.com/articles/4-principles-reduce-cognitive-load/] T2
14. **Mobile: labels go above the field, never to its left** — left-aligned labels compress the visible input width on small screens. Labels must also be context-independent ("Billing Phone," not "Phone") since a user can lose surrounding context while scrolling. Never split one logical value (full name, phone, ZIP) across multiple inputs. [source: https://baymard.com/blog/mobile-checkout] T2
15. **No disappearing/floating inline labels** — they create false simplicity and force the user to delete their input just to re-read what the field was, especially bad when recovering from an error. [source: https://baymard.com/blog/mobile-checkout] T2
16. **Guest checkout must be visually equal-or-above sign-in/create-account, positioned above the fold.** Baymard mobile testing found 60% of test subjects failed to even locate the guest-checkout option when it wasn't prominent. [source: https://baymard.com/blog/mobile-checkout] T2
17. **Order summary placement on mobile: pinned near the top, expanded (not collapsed).** "Show the order summary prominently at the top of the checkout pages. Don't make shoppers scroll to the bottom" — subtotal, tax, fees, discounts, shipping all visible, not accordion-hidden. [source: https://www.nngroup.com/articles/mobile-checkout-ux/] T2
18. **60% of top-50 mobile sites still fail to trigger the correct input keyboard** (numeric for card/phone, email-optimized for email) — a measurable, common miss. [source: https://baymard.com/blog/mobile-checkout] T2
19. **EAS sequence for trimming a checkout form:** Eliminate nonessential/nonurgent fields first, Automate by inferring/prefilling (ZIP → city/state), then Simplify remaining inputs with defaults and smart formatting — apply in that order, not simultaneously. [source: https://www.nngroup.com/articles/eas-framework-simplify-forms/] T2
20. **Payment-choice paralysis:** limit visible payment options and use branded, explicit third-party buttons ("Checkout with PayPal") so the redirect is expected, not a surprise click. [source: https://www.nngroup.com/articles/mobile-checkout-ux/] T2

## Diagnostic Checklist

1. **Symptom:** users bail right before or during payment entry → **Check:** does the total price (incl. tax/shipping) appear anywhere before the final payment step, or only at/after checkout starts? → **Violation:** cost-surprise-at-checkout [source: https://baymard.com/learn/checkout-flow-ux-optimization]
2. **Symptom:** the confirm/review screen feels ambiguous about whether tapping commits the purchase → **Check:** is the CTA copy generic ("Continue"/"Submit") vs explicit ("Place Order")? → **Violation:** vague-CTA-label [source: https://baymard.com/learn/checkout-flow-ux-optimization]
3. **Symptom:** card entry feels untrustworthy despite being on HTTPS → **Check:** is the payment block visually encapsulated (border/bg) with 1-2 badges directly adjacent, or are card fields styled identically to every other input? → **Violation:** missing-payment-field-encapsulation [source: https://baymard.com/blog/perceived-security-of-payment-form]
4. **Symptom:** users retype fields or complain the form "cleared" after an error → **Check:** does the error message sit inline next to the specific field with specific language, and does the field retain its prior value? → **Violation:** generic/destructive-error-handling [source: https://baymard.com/learn/checkout-flow-ux-optimization + https://www.nngroup.com/articles/4-principles-reduce-cognitive-load/]
5. **Symptom:** form feels disorganized or fields seem out of order on wider viewports → **Check:** is the layout single-column top-to-bottom, or does it zigzag across two columns? → **Violation:** multi-column-form-ambiguity [source: https://www.nngroup.com/articles/4-principles-reduce-cognitive-load/]
6. **Symptom:** mobile typing feels slow/error-prone → **Check:** are labels positioned above (not left of) fields, is the numeric/email keyboard triggered per field type, are logical single values split across multiple inputs? → **Violation:** mobile-field-layout-mismatch [source: https://baymard.com/blog/mobile-checkout]
7. **Symptom:** guest users can't find a way to skip account creation → **Check:** is guest checkout visually equal-or-above sign-in, placed above the fold? → **Violation:** buried-guest-checkout [source: https://baymard.com/blog/mobile-checkout]
8. **Symptom:** billing-address section feels like duplicate data entry → **Check:** does "same as shipping" default to checked, is Address Line 2 hidden by default? → **Violation:** redundant-field-entry [source: https://baymard.com/learn/checkout-flow-ux-optimization]
9. **Symptom:** order total is hard to find while scrolling the form → **Check:** is the order summary pinned near the top and expanded, or buried at the page bottom / collapsed by default? → **Violation:** buried-order-summary [source: https://www.nngroup.com/articles/mobile-checkout-ux/]
