# Taste audit wave 1 (2026-07-15) , 5 surfaces vs the researched floors

Method: full-page captures of the RENDERED product (dev server, dev-login for dashboard), one fresh-context auditor per surface grading against RATIONALE.md + research/TASTE_*.md; homepage additionally carried a live DOM metrics dump and a Gemini second-eye pass. Findings severity 0-4 (frequency x impact x persistence). Visual version: public/_mockups/taste-audit-w1/. Screenshots: _audits/screenshots/taste-w1/.

## Customer homepage /de (9 findings)
- **S4 Type-size budget blown: 14 distinct font sizes on one screen (hard cap is 4)**
  - evidence: DOM metrics (metrics-home.json) count 14 distinct sizes rendered on this single page: 11, 12, 13, 13.5, 14, 15, 16, 17, 18, 20, 22, 28, 40, 44px. Five values cluster inside an 11-15px band doing the same 'meta/label' job with no visible role difference, and five values (13.5, 17, 22, 28, 44) fall completely outside the locked hand-tuned ladder (11/12/14/15/18-20/24/40).
  - floor: RATIONALE.md section 5, retrofit block 'Per-screen type budget (LOCKFILE:319)': hard rule, <=4 distinct sizes / <=2 weights per screen, T1 (Ware/Bertin: each added size is a distractor class that dilutes the hierarchy signal). Corroborated by research/TASTE_TYPOGRAPHY.md checklist item 1: 'Violation if >3' sizes, target 2-3.
  - fix: Snap every text run to the nearest of the 7 canonical ladder steps; the 5 off-ladder values (13.5, 17, 22, 28, 44) are the first to fix, and the 11-15px meta cluster should collapse onto one shared token.
- **S3 Sub-44px touch targets on primary nav, city selector, and the signup CTA**
  - evidence: Measured DOM rects (metrics-home.json smallTargets): 'Anmelden' CTA 108x39px, 'Stadt wählen' 100x36px, 'Services' 99x37px, 'Für Unternehmen' 157x37px, 'Inspo' 60x37px, 'Über uns' 60x21px, hero search 'Service' 75x33px and 'Stadt' 61x33px. Every one of these is below the floor; 'Über uns' at 21px is under half of it. Visually, the carousel prev/next arrow buttons also measure ~35px diameter (pixel-measured from the screenshot at 'Top auf Solen').
  - floor: Project CLAUDE.md design contract: 'touch target: interactive controls >=44px (h-11), the a11y floor.' RATIONALE.md section 6: WCAG 2.5.5 AAA 44x44 / Apple HIG 44pt (T1), deliberately locked above the legal AA 24x24 minimum.
  - fix: Pad the header nav links, city selector, and hero search fields up to a 44px hit area via padding (not visible size growth) ,  the same hit-area/visible-size split already locked for HeartButton (44px hit / 32px visible).
- **S3 Green 'Live' status text fails WCAG AA contrast (3.3:1, floor is 4.5:1)**
  - evidence: Measured pair (metrics-home.json): text '#16a34a' (s-success green) on white background, 12px, contrast ratio 3.3:1. Location: the Walk-in module subheader, '● Live' directly under 'Ohne Termin. Sieh die Wartezeit...'.
  - floor: RATIONALE.md section 4 measured token table already documents this exact pair: 's-success #16A34A as TEXT on white | 3.30:1 | Fails AA for normal text... the pastel-chip pattern (ink text + green icon) is the conforming form.' This instance renders the failing form (green text), not the documented conforming one.
  - fix: Swap to the locked conforming pattern: ink-colored 'Live' label text plus a small solid-green dot/icon carrying the color, instead of coloring the text itself green.
- **S3 One-ink-anchor rule broken on every salon card: three bold-ink elements instead of one or two**
  - evidence: Zoomed crop of the 'Muse Beauty Studio' card (and confirmed identical on all 10 visible cards across both carousels): the name is bold ink, and BOTH '14:30' (time) and 'CHF 80' (price) render at the same near-black bold weight as the name ,  only the address line is grey/secondary. Three same-weight ink anchors compete on one card.
  - floor: LOCKFILE card grammar 5-step recipe (LOCKFILE:1301-1311, retrofitted in RATIONALE.md section 14): step 5 is 'one differentiated element.' CLAUDE.md taste rule 5 / V3-D442 amendment: a card may carry at most two ink elements (name + price), and only when the NAME is larger so size marks the anchor ,  never three same-weight ink runs.
  - fix: Drop the time ('14:30', 'Mo. 09:00' etc.) to the same grey ink-2 weight as the address line, leaving name + price as the only two ink elements, with name staying visibly larger.
- **S3 Banned em-dash character rendered as unlabeled UI copy on every salon card**
  - evidence: A bare ', ' glyph appears immediately after the salon name on all 10 visible cards in both carousels, e.g. 'Muse Beauty Studio , ', 'Old Town Barbers , ', 'Glow Lab Basel , ', with no attached label ,  most likely an unresolved rating placeholder rendering as a stray character.
  - floor: Project CLAUDE.md taste rule 10: 'No em-dashes ,  anywhere in UI copy, code, comments, or commits.' This is a hard, repo-wide, machine-checkable ban, not a style preference, and it is showing up in shipped customer-facing copy.
  - fix: Replace the dash with the real rating (star + count) when review data exists, or omit the slot entirely when it doesn't, per the no-fabricated-data rule ,  never render a bare, unlabeled dash.
- **S2 Cookie consent banner occludes the 'In der Nähe' card row mid-page**
  - evidence: In the capture, a translucent 'Wir verwenden Cookies' banner sits directly over the top of six salon photo thumbnails in the 'In der Nähe' carousel, washing out the image tops and becoming the visually loudest element at that scroll position.
  - floor: research/TASTE_HIERARCHY.md finding 6-8 / squint test: at most 1-2 elements should win the focal contest on any given view; a system-chrome banner outranking primary content fails that test outright.
  - fix: Verify live before changing code ,  full-page screenshot stitching is a known artifact for position:fixed elements. If the banner genuinely renders mid-scroll rather than pinned to a viewport edge, fix its CSS positioning; if it's a capture artifact only, no change is needed.
- **S2 'Finde deine Inspiration' section: six blank dark rectangles become the single heaviest visual block on the page**
  - evidence: All six TikTok cards in the Inspo carousel render as solid near-black gradient rectangles (~300x520px each) carrying only a 'TikTok' chip and a heart icon ,  no thumbnail image loaded in any of them.
  - floor: research/TASTE_HIERARCHY.md checklist item 2 ('if you emphasize everything, nothing gets focus') applied in reverse: an unintended content-free block outweighs every real focal element by sheer size and darkness. Project memory feedback_rich_not_bland: customer surfaces must render rich, never sparse/monochrome blocks.
  - fix: Confirm whether this is the known Inspo-imagery-expiry issue (TikTok thumbnails expire; the storage proxy is supposed to persist bytes) or a load-timing capture artifact; ship a designed empty/error state either way, never a bare dark rectangle.
- **S1 Walk-in module: both slot cards show permanent skeleton loaders, never resolve to content**
  - evidence: Both cards under the 'Walk-in · Live' header render grey skeleton bars only ,  no salon name, wait time, or price appears anywhere in the capture.
  - floor: Design contract states matrix: Skeleton is a transient loading state, not a terminal one. Project CLAUDE.md's documented #1 failure mode is a control that looks wired but silently does nothing.
  - fix: Verify live whether Walk-in data resolves after this point (the screenshot may predate the fetch) or the fetch silently fails; if the latter, apply the silent-no-op discriminate-check pattern from fable-backend.
- **S1 Footer copyright bar renders a multi-word phrase in ALL-CAPS**
  - evidence: The bottom bar reads '© 2026 SOLEN.CH   SCHWEIZ' fully capitalized ,  a multi-word phrase, not a single glanceable label.
  - floor: research/TASTE_TYPOGRAPHY.md finding 8 / checklist item 5: caps are only safe for a single short glanceable label; multi-word phrases degrade legibility once capitalized (NN/g glanceable-fonts, T1).
  - fix: Set the copyright line to normal sentence case; keep only the locale codes (DE/EN/FR/IT) capped since those are genuinely single-token abbreviations.
