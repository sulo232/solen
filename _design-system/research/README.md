# research/ , what a research file is, and what it has to earn

**The finding that made this file worth writing: the template already existed, nobody had written it
down, and three files break it.** All 26 files here were checked on 2026-08-08, and the shape is
remarkably consistent without ever having been specified:

- **25 of 26** end in a rule, not in observations.
- **23 of 26** carry a source you could go and check: a URL, a measurement, a screenshot, a sample.
- **21 of 26** quote his own verdict somewhere.

So this is not a new standard being imposed. It is the standard that was already being met, written
down so the next file cannot quietly fall below it.

## The four things a research file must have

1. **A question it exists to answer**, in the title or the first line. Not a topic. "Why do our
   screens read flat" is a question; "Typography" is a filing label.
2. **A source anyone could check.** A URL, a measurement with the method named, a screenshot path,
   the app and screen it was sampled from. **"Studies show" with no source is a myth wearing a
   number**, and this estate has already debunked several of its own (`+2,000% from samples`,
   `70-90% never change defaults`). Attach the source, soften to a qualitative claim, or cut it.
3. **A rule at the end.** Research that stops at findings has not finished. The last section says
   what changes as a result, in a form someone could follow tomorrow. If nothing changes, say that
   in one line, and that is a legitimate result.
4. **His verdict, verbatim, when there is one.** Where he has looked and said yes or no, that quote
   outranks every reference and every measurement in the file.

## The two failure modes it exists to prevent

**Evidence that never becomes law.** A file full of correct findings that no rule ever cites is work
nobody can act on. If it produced a rule, the rule belongs in the canon file that owns that concern,
and this file becomes its evidence. The pointer goes both ways, or the rule drifts from its reason.

**Law with no evidence.** The reverse is worse and this estate has had it repeatedly: a rule
everyone follows whose original reason nobody can find, so it cannot be argued with and cannot be
retired. `RATIONALE.md` exists for exactly this and points here.

## The three files that do not meet it, named rather than quietly fixed

- `TASTE_HIERARCHY.md` , ends in observations with no rule, so nothing can be followed from it.
- `TASTE_CHECKOUT.md`, `TASTE_DASHBOARDS.md`, `TASTE_TYPOGRAPHY.md` , no verdict of his recorded,
  so they rest on references alone.

Named rather than repaired, because repairing them means re-doing the research or asking him, and
inventing a rule to make a file look complete is the worse outcome by a distance.

## Where a file goes when it is done

Dated investigations stay here. If it produced a rule, that rule moves into the canon file that owns
its concern (`LOCKFILE` for a literal, `SOURCE` for applied law, `MOTION`, `COPY_LAW`, `PSYCHOLOGY`)
and cites this file. A research file is never itself the law, because law that lives in a dated
report gets read once and then drifts.
