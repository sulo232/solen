My recommendation: A (keep system mono)

The mono is used in 3 places total: gift codes (`/salon/[slug]/gift-card`), voucher code display (`/vouchers/buy`), and a few `/account/messages` code snippets. Low-stakes, low-visibility surface. Adding a custom mono font adds 40 KB / weight + a font-loading flicker on first paint — for a payoff most users will never consciously notice.

System mono on iOS (SF Mono) is already excellent for code rendering. The Swiss CHF amount with the system mono looks crisp + native. Locking a custom mono is a P3 polish that probably doesn't earn its cost.

Pick B (JetBrains) if codes are about to become MORE visible (e.g. you add a coupon-code billboard, ticket-stub UI, or anywhere the code IS the hero). The 0/O legibility is genuinely better.

Pick C (IBM Plex) if you want subtle brand tie to Inter Tight's humanist feel — Plex Mono has the same attitude. Better matched typographically but less utilitarian.

  • Cost of A: 0 KB, 0 flicker, 0 LOCKFILE entry — system fallback.
  • Cost of B/C: ~40 KB additional weight, 1 LOCKFILE entry (`font-mono` family lock), 1 layout.tsx font import.
