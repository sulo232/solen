My recommendation: B (Deep #185CE0)

Why: keeps the "Solen blue" identity (same hue family) but moves the lightness from 60% → 49% — closes the RGB gap with the pale background, kills the vibration. Already exists in the LOCKFILE as s-accent.deep (originally just for hover states) so zero new tokens.

Why not C (Navy): Uber's #003366 is so dark it stops feeling like "accent" and starts feeling like ink. Solen's hue language is royal-blue-as-spotlight, not navy-as-default-text. Navy is closer to Bloomberg/Capital-One — different identity.

Why not D (Ink + icon): elegant but the accent footprint shrinks too much. You'd lose the blue moment on links, badges, eyebrows — those become just "another text run." Linear can pull this off because their accent is literal sparkles + headers; Solen uses blue as the only chromatic break in a B&W system, so killing the text-color use removes one of the two surfaces where you SEE the accent.

If you pick B — what gets swept

  • ~12-18 callsites where text-s-accent appears at sizes 9-13px on a pale bg
  • Add a semantic class text-s-accent-text = #185CE0 (deep variant alias for body-size text)
  • Keep text-s-accent (#276EF1) for icons + large headings (where geometry breathes)
  • Update LOCKFILE §1 with the split-role rule
