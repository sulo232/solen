Design notes (internal — not product copy)

  • Where it slots in. The guest form is the logged-out variant of booking Step 4 — Review & confirm (Fresha flow: service → time → professional → review). A logged-in user skips straight to the saved-details summary; a logged-out user sees the Continue as guest / Log in switch and the three fields.
  • Fields mirror the existing orphaned GuestBookingForm.tsx: full name (required, min 2 chars), mobile number (required, +41 prefix locked, ^\+41[0-9]{9}$), email (optional, only validated if filled). The +41 country chip replaces a typed prefix so the regex can't be broken by spacing.
  • Aesthetic = LOCKFILE / CANON. Inputs at rounded-input 16px on hairline s-border; focus = s-accent #276EF1 border + s-accent-pale glow (the only place blue appears, per §1.5 functional-only). Error state uses s-error #D32F2F — the old component wrongly used text-s-accent for errors; corrected here. Labels are sentence-case 13px s-ink, not the old 9px uppercase tracking-.18em.
  • Primary CTA stays ink (bg-s-ink, §0.2). Sentence case, 15px / 500. Never accent-blue.
  • Prepay + review-first disclosure (D11 / D12 / §11). Full prepay at booking with the card saved off-session; refunds are reviewed by the salon (no auto-refund). Cancellation/no-show fee is the policy-automated lane, disclosed and accepted here at booking via the consent checkbox.
  • Order number hook. Phone hint ("we'll text your booking number") sets up the reference_code shown on the confirmation screen (separate mockup). Email is the optional second channel for the access link.
  • Sample data is realistic Swiss: Maison Lumière, Zürich; women's cut + gloss with stylist Lena; CHF pricing; +41 mobile format.
