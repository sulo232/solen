What broke, in plain terms

The money guard switches itself off

A folder named cron or webhook anywhere in the path disarms it completely, before it reads a single line. A payment route under such a folder has no guard at all.

The private-data guard only sees one spelling

It catches asking the database for everything with select("*"). Write select("*, bookings"), which is the form actually used here, and it sees nothing.

The column guard misses the exact bug it was built for

It exists because of the one-click confirm link in your emails having no protection against being clicked twice. It does not catch that case.

The bypass is printed in the error message

One check tells you to run a command to prove you measured something. Running that exact command is a complete bypass of both of its hardenings.

The pre-launch check has never caught its own case

It only fires on the literal word "customer", so every other way of claiming a bug hurt real people walks through.
