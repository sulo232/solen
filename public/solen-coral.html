Proposed lock

WCAG AA is the floor, not the ceiling. Body text ≥4.5:1. Large text + UI (buttons, focus rings, icons that carry meaning) ≥3:1. Disabled states are exempt (they signal unavailability). Live-Activity card spec
  • Single slot, single state at a time — never a stack of cards. Does NOT auto-rotate. Server picks the highest-priority state per the order above and the card stays put until underlying data changes.
  • Priority resolution: 1 Upcoming → 2 Loyalty close (≤2 stamps) → 3 Deal at favorited salon (today) → 4 Review reply (last 7d) → 5 Rebook nudge (avg-cycle reached) → 6 Empty CTA fallback. Pick the first one that qualifies.
  • Morph animation: only fires when the resolved state CHANGES (e.g. user just made a booking → "Upcoming" appears; appointment passes → falls back to next priority). Cross-fade + 4px Y slide over 400ms. Per Q35 timing. No animation on initial load — card just appears in its current state.
  • Visual register per state: coral-amber gradient = positive momentum (Upcoming, Loyalty); ink-gradient = urgency (Last-minute deal); cream = soft notification (Reply); neutral = quiet nudge (Rebook).
  • Tap target: entire card is tappable, routes to the relevant page (booking detail / salon's loyalty / salon's deal page / review thread / salon's rebook flow).
  • Reduced-motion: instant state swap, no slide, no cross-fade (per Q36 prefers-reduced-motion).
  • Refresh cadence: client polls `/api/profile/live-state` every 60s while page is visible; revalidates on focus + on booking-create / review-reply websocket events.
  • Empty state: if no signal qualifies, show coral-warm "Salon entdecken →" CTA (per Q21 line-art SVG could anchor this).
