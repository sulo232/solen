Honest take on Lottie before you pick

What Lottie is good at
✓ Easy to USE — `npm install lottie-react`, drop in a JSON, done
✓ Ready-made library: lottiefiles.com has 200k+ free + paid
✓ Brilliant for hero moments, loading states, success animations, onboarding
✓ Scales infinitely (vector), can drive via state machines (Rive too)
Why it's overkill for tile icons at 28–48px
⚠ Each Lottie JSON = 30–300 KB vs inline SVG ~1–3 KB
⚠ Animation barely registers at 38px — users miss motion at thumbnail size
✗ Hard to MAKE from scratch (needs After Effects + bodymovin)
⚠ Loading 3 Lotties on the homepage = ~150 KB extra payload for vibe
Can I author one? Render existing JSON: yes (trivial). Hand-write JSON: impractical. Generate procedurally: technically yes via lottie-web API, but slow path.

My pick: B (Phosphor duotone)

Best ROI at tile-icon size. Premium look (Linear/Vercel-tier), free, MIT-licensed, ~2KB per icon. Harmonizes with the oil paintings because both read as "editorial design vocabulary" — the icons don't compete with the illustrations, they sit one rung down on the visual hierarchy.

Second pick: C (hand-sketch) if you want the icons to feel ART, not just functional. But it takes longer to nail the line quality.  Skip Lottie for now — overkill at 38px. Revisit if/when you want big animated icons in onboarding or the empty-state of a feature page.
