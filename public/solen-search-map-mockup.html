My recommendation: ship (i) — toggle on same page

The map and list are two views of the same data with the same filters. That's an Airbnb / Booking pattern — they don't split into separate routes. They use one URL with a ?view=map param or just toggle in-place. Same SEO impact (canonical URL stays single), but easier to share + simpler to maintain.

Implementation if you pick (i) toggle:

  • Add ?view=map URL param to /de/search
  • SearchTemplate reads it, conditionally renders MapView or ListView
  • The existing map button in the search bar swaps to a "Liste" button when in map mode
  • Mobile pattern: card strip floats at bottom of map (Airbnb pattern shown above). Swipe horizontally = pan map.
  • Desktop pattern: 70/30 split — map left, scrollable card list right. Click pin = highlight card. Click card = pan map to pin.
  • Build estimate: 1 day. Reuses existing salon-card primitive + existing API. New piece is the Map component (Leaflet or Mapbox).

If you pick (ii) two routes instead:

Same UI, but path becomes /de/search/map as a separate page. Gives you separately-indexed SEO surface ("Coiffeur in Basel — Karte"). Worse for in-session toggling (full route nav vs query param swap). Marginally better for deep-linking + sharing.

Things to decide BEFORE building either:

  • Map provider: Leaflet+OpenStreetMap (free) or Mapbox (paid, prettier). Recommend Mapbox — Solen needs Swiss-quality tiles.
  • Clustering: when 50+ pins in viewport, group into "10+" cluster bubbles? (Airbnb does.) Yes — otherwise mobile becomes unreadable.
  • Default starting viewport: city centroid + 14 zoom level for Basel/Zürich/Bern. Should the map respect the URL's city filter? Yes.
  • What happens with no pins: empty-state in middle of map = "Keine Salons in diesem Bereich. Verschiebe die Karte oder ändere Filter."
