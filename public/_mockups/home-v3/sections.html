sec-personal The logged-in rail. Three states, because personalization has three real levels of evidence and only one of them can be true today.

State A , signed out. This is what renders pre-launch, and it renders nothing. That is not a gap in this mockup, it is the shipped behaviour: ForYouSalonRows.tsx returns null with no prefs, ForYouGreeting.tsx returns null when logged out, and useCustomerPrefs.ts short-circuits on getSession() so a guest never even calls /api/profile. Drawn as an empty slot rather than as invented product UI.

Section not rendered The feed goes straight from sec-popular to sec-cities. No sign-in prompt, no teaser card, no placeholder row. Nothing was designed here because nothing ships here.

State B , signed in, no completed bookings. Every account is in this state right now, so this is the one honest signed-in render. The reason line is a stored fact: the category the user picked during onboarding, read from profiles.customer_preferences.categories. The three salons are the real ones this rail already picks.

The six inactive cities (zuerich, bern, luzern, geneve, lausanne, neuchatel) are deliberately NOT drawn. /api/cities cannot return them, drawing them would need a new endpoint, and six untappable tiles is six dead affordances. If you want them visible as a coming-soon list, that is a product call and it needs a real destination behind each one first.
