The walk-in row is missing a photo it already has

The other three category pages fail these same checks by having almost nothing on screen. This one fails by having something on screen twice, once with a photo and once without.

Both screens below are the real, running page. The only difference is one thing added: a photo. Every number in a badge is computed by this page reading the real one live, not typed in by hand.

Why this page and not the other three. Barbershop is the only category page that renders the walk-in row (it is switched on by name, category by category, in the code: "walk-in is genuinely barbershop-only"). That row is real and wired, it shows live queue data for real salons, it is not decoration and this file does not propose removing it. But it currently repeats each salon's name and star rating a second time in bold, with no photo, a few rows under the first, photographed mention of the same salon. That is where most of the extra bold text comes from, and where the missing photo area goes.
What adding the photo does and does not fix. It raises the photographic share of the screen using zero new photography, real ones the page already fetched. It does not, on its own, clear the 33% floor: four small thumbnails are not enough area by themselves. It does not touch the biggest-text floor, the bold-text floor, or the too-many-sizes floor, because every element behind those three belongs to either the salon card (locked sitewide: name and price are both bold by design) or the section titles and the walk-in row itself (the same shared pieces the homepage and the other category pages render, not something this one page can change alone without changing all of them).

Three floors need your call, not a CSS fix

The biggest-text floor, the too-bold floor, and the too-many-sizes floor all trace back to parts of the page that are either locked (the card's name+price are both bold, on purpose, sitewide) or shared with the homepage and every other category page (the section titles, the walk-in row). Changing them only on this page would fix this page and quietly break consistency on the others the moment it shipped.

Leave them as they are Accept that a category page rich enough to have real photos and a live walk-in feed will run over the bold-text ceiling, because the ceiling was written before this page had this much real content. Nothing changes beyond the photo above.
Reopen one shared rule, sitewide Pick ONE lever and change it everywhere it appears, not just here: either the walk-in row stops repeating the salon name in bold (it is already named once, with a photo, a few rows up), or the rail section titles (used on this page and on the homepage) get a real size increase past 28px. Either one is a sitewide type change, which is bigger than this one page, so it needs a mockup of its own before it touches real code.
What this file does not do. It does not resize or re-weight the salon card. It does not touch the section titles. It does not add, remove, or reorder a single card or rail. It does not restore the featured-hero carousel the owner removed from this exact page on 2026-07-02, or the walk-in category pill removed on 2026-07-31, both checked against the graveyard before writing this file. The only change is the photo, and it is reversible by deleting the small script at the bottom of this file.
