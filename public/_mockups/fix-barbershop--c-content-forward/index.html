What changed: the first row of real barbershop cards, the one already at the top of the page today, gets wider. The category buttons above it also lose a little of their own padding, so the row sits a bit higher too. Nothing else on the page moves: the walk-in queue block underneath is left exactly as it is.
What this gets you, and what it does not: real photo area on screen goes up by a few measured points, roughly a fifth more photo than before, using photos the page already has. It does not clear the thirty-three percent target on its own: this screen can only fit about one full card at a time no matter how wide it gets, so growing that one card runs out of room well before it reaches a third of the screen. And the same trade the home-page version of this fix already named applies again here: wider cards means less of the next salon peeks into view per swipe, a size you approved once before at the current width.
Why this page is different from its neighbours. Barbershop is the one category page with a real, live walk-in queue block sitting right under the top row. A separate mockup at floor-fix-barbershop shows fixing THAT block, by giving it a photo it is currently missing. This mockup does the opposite: it leaves the walk-in block alone and grows the row above it instead. They are two different real fixes to two different real rows on the same page, not two versions of the same idea.
Both panels are the same live route, not a redraw. Every number on this page, before and after, is read directly off the real rendered DOM by the script at the bottom of this file, the same way the site's own floor-check script reads it, not typed in by hand and not estimated.
