What actually changed, in plain terms. Two things. Second, inside the walk-in box, the wait-status word got much bigger and is now the one thing on the page your eye lands on first; everything else in that box (names, star ratings, the live-status label) got lighter, not bold, because a page that bolds nine different things has no real emphasis left to spend.

Two changes here reach past this one page

Both fixes above touch a shared piece, not just barbershop. Widening the cards reopens a dated, owner-approved sizing rule (R4-2) that also sets the card width on the homepage rails and every other category page. Retyping the walk-in row edits a component the homepage imports directly, so the same status word and the same duplicate bold name would render lighter and bigger there too the moment this ships.

Approve both, sitewide The homepage rails and the other three category pages pick up the wider cards and the retyped walk-in box the next time they render, automatically, since it is the same component. One decision, cleans up more than this one screen.
Approve for barbershop only, for now Needs a small code fork (a page-scoped className instead of the shared one) so the homepage and the three other category pages keep today's narrower cards and bolder walk-in text until a separate decision widens the rollout. Costs a bit of near-term inconsistency between this page and its siblings to avoid changing anything the owner has not looked at yet.
What this file deliberately left out. The one component built specifically for "more photo on a category page," CategoryHeroCarousel.tsx, a full black photo hero with real salon photos and ratings, sits unused in the codebase. It is not in either panel above. The owner removed this exact shape from this exact kind of page earlier this year for clashing with the current card style; that entry lives in the graveyard (_design-system/REMOVED.md line 49) and this file checked it before writing a line of the after panel. Also left out: real photo thumbnails on the four walk-in cards (the sibling floor-fix-barbershop file's own technique), because that file already measured the honest result of that one change alone and it does not clear the floor either; stacking an unverified guess about the combination on top felt worse than reporting the shortfall plainly.
What this file does not touch. No section added, removed, or reordered. No card added or removed. Nothing about the salon card's own name/price bold rule (locked sitewide, V3-D442). Card shadows and elevation are untouched; that floor already passes. No German copy anywhere the real page owns; both iframes render the real localized page through the product's own translations.
