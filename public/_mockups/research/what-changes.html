SOLEN, RESEARCH SUMMARY, ONE PAGE

What actually changed, and what did not

The research this answers lives in four files nobody had opened. This page is the same findings, read on a phone, with the file and the reason attached to every line.

Airbnb's account screen runs on almost no colour: one dark ink for every word, one light grey for the few lines that separate sections, and their pink brand colour shows up in exactly one place, the icon for whichever tab you are currently on at the bottom of the screen. It has no boxes. Every row sits straight on the page with a small, fixed gap to the row below it, and that gap only gets noticeably bigger once, right where one group of options ends and the next one starts. Nothing is made bold or coloured just to look finished, weight and colour are spent on the one thing that is actually the point of the screen and nowhere else.

1Already done, with proof

Five changes shipped in real code today on /de/profile, the live page, not a mockup. Every value below is quoted from the file as it stands right now.

Shipped

Notification bell

WAS

Rendered on every route, unconditionally.

NOW

{!isAccountHub && <NotificationBell hidden={menuOpen} />}, hidden on the account hub only.

app/[locale]/_components/layout/Header.tsx

A bell is a notice about something happening somewhere else. This screen's job is your own account, so a notice about something else does not belong in its own top row.

Shipped

Hamburger menu

WAS

A bordered white square button, opening the sitewide menu, on every route.

NOW

Hidden on the account hub, gated on the same condition as the bell.

app/[locale]/_components/layout/Header.tsx

The account hub's own rows (Bookings, Wallet, Settings) already are its navigation. A second button opening a different menu belongs to a different screen's job.

Shipped

The row container (the box)

WAS

divide-y divide-s-border rounded-[24px] border border-s-border: every group of rows sat inside a bordered, rounded box, with a line between every row inside it.

NOW

bg-white only. Rows sit straight on the page: no border, no rounded box, no line between rows in the same group.

app/[locale]/_components/profile/AccountHub.tsx (the box), app/[locale]/profile/loading.tsx (the loading skeleton, so the page never flashes the old boxed look for a second before real data arrives)

Measured on Airbnb's own screen: zero boxes anywhere. Solen's own written design rules already say an account hub gets no container, and never both a box and a line between every row. This was Solen's own rule being broken, not a new opinion arriving from Airbnb.

Shipped

The grey square behind each icon

WAS

A 38x38px filled grey square (bg-s-bg-sunken rounded-[14px]) sat behind every row icon.

NOW

A bare 22x22px icon, nothing behind it.

app/[locale]/_components/profile/AccountHub.tsx

Airbnb's icons sit bare on white, nothing behind them. The grey square was also breaking Solen's own rule against dead, meaningless grey shapes.

Shipped

The back control

WAS

A white, bordered, rounded-square 44x44px button, the same shape used for every icon button on the site.

NOW

A filled light grey circle (#F2F2F2), no border, still 44x44px so it stays easy to tap.

app/[locale]/_components/layout/Header.tsx

Measured directly off the owner's own reference screenshot: Airbnb's own back control is a filled grey circle, no border. Ours was a bordered square, which is exactly why it never read like the reference.

2The same research, on three other screens

Nothing above is specific to the account hub. It comes from one shared header component and six general principles, so here is what each one means for the home feed, a category page, and Inspo. Every number below was measured live today, at phone size (390 wide, 844 tall), not carried over from an older note.

Home feed  /de

WHAT CHANGES

Nothing in the top row. It was already right before this research started.

WHAT STAYS THE SAME

One hamburger icon lives inside the search pill. No separate bell, no separate menu button. Measured live: exactly 1 visible menu icon, 0 bell icons, in the first screen.

WHY

The home feed's job genuinely is "get to anywhere on the whole site," so folding the site menu into its own search bar is the right place for it, the same underlying idea as Airbnb's own account screen: their icon strip at the bottom of the screen owns that job, so their account screen does not need to repeat it.

Distinct text sizes in the first screen: 6 (12, 12.5, 13, 14, 16, 18px)
Share of visible text at bold/semibold weight: 25.5% (13 of 51 elements)
Bordered elements in the first screen: 2, the search pill (one tappable control) and the nearby map tile (a photo card)

STILL TO CHECK, NOT MEASURED THIS PASS

Whether a returning user's next booking (when there is one) gets its own bigger, separate spot above the general feed sections, the same way Airbnb gives its one promoted card its own spot above the flat rows. Checking this honestly needs a logged-in test user with a real upcoming booking, which this pass did not fetch.

A category page  /de/coiffeur

WHAT CHANGES

Nothing. Same result as home.

WHAT STAYS THE SAME

Same pattern as home: one hamburger icon inside the search pill, no bell. Only one bordered element found on the whole visible screen, the search pill itself. Every result under it is a real salon card with its own photo and soft shadow, the entity-card treatment already in use everywhere else.

WHY

A category page's job is also "browse everything in this category," a whole-site kind of job, so the same reasoning as home applies. And a card that holds one distinct, comparable salon earns its own edge on its own, that was never the account-hub mistake, where identical navigation rows got a box for no reason at all.

Distinct text sizes in the first screen: 5 (12, 13, 14, 16, 18px)
Share of visible text at bold/semibold weight: 2.2% (2 of 90 elements)
Bordered elements in the first screen: 1, the search pill

WORTH A NOTE, NOT A VIOLATION

2.2% bold is well under any ceiling this project has written down. If anything this screen reads as under-emphasized rather than over. Not a problem today, just worth knowing the number.

Inspo  /de/inspo

WHAT CHANGES

Nothing shipped here today, but one real gap turned up while measuring, see below.

WHAT STAYS THE SAME

The filter panel is a dropdown overlay, which is allowed to have its own edge (an overlay is one of the legitimate boxed cases in Solen's own rules). The category pill row (the first pill active, three unselected pills after it) is neutral white and grey, no colour on the pills that are not active. Both already match Solen's own written rules.

WHY

Same reasoning as the other two screens for the pills; overlays are a named exception to the no-box rule because they float above the page rather than sitting inside a plain list.

Distinct text sizes in the first screen: 3 (12, 14, 16px)
Share of visible text at bold/semibold weight: 7.7% (1 of 13 elements)
Bordered elements in the first screen: 1, the search pill

A REAL FINDING, NOT A FIX, FROM MEASURING LIVE TODAY

On the home feed and the category page, the slot at the right edge of the search pill shows the hamburger icon. On Inspo, that same slot shows a heart/save icon instead, and the hamburger element that exists in the page's own markup measured at zero width and zero height, meaning it never actually appears on screen. So right now, unlike the other two screens, Inspo has no visible way to open the sitewide menu from its own top row. This was not chased further in this pass (it needs its own look at the component, not a guess), it is flagged here so it is not lost.

STILL TO CHECK, NOT MEASURED THIS PASS

Whether any tile in the photo grid, a currently trending look, or one that matches your own saved style, gets its own promoted spot the same way Airbnb reserves one bigger card above its flat rows. The real grid had not finished loading real photos during this pass to check tile by tile.

3What we are not copying, and why

  • The bar of icons at the bottom of every screen. Airbnb's five-icon bar at the bottom of the screen is their whole site's navigation. Solen does not have one, and the owner turned one down in plain words on a prior date. That is a settled call already on record, not an oversight this research reopens.
  • Their typeface. Airbnb's app uses a font of their own called Cereal, which only they can use. Solen uses Inter and Inter Tight everywhere. By coincidence, the row label size on the account hub already lands within half a pixel of the same 16px both systems use, but that is two separate measurements landing close together, not one font copying the other.
  • Rows with nothing extra written on them. Airbnb's account rows are pure navigation with no second line of text, because there is nothing live to put under "Get help" or "Legal." Solen's rows carry real, current numbers: your next appointment date, how many stamps remain until a reward, how many vouchers are active. Deleting those to look more like a screen with nothing to show would be hiding real information to chase a look, which is not an actual improvement.

4Still open, no call made yet

Five real questions below. Each one names a real cost on both sides. None of them are decided here.

1. Plain white rows, or a light grey block behind the group?

Rows currently sit on plain white with nothing marking where a group's own edge is.

Cost of adding a grey block: it puts back a visual device right after removing one, and it stops matching what was actually measured on Airbnb's own screen.

Cost of staying plain white: on a small phone screen, a plain list with nothing anchoring it can read as unfinished rather than deliberately calm.

2. Match the exact divider grey, or keep Solen's own token?

The line between groups is currently Solen's one standard grey (#E4E4E7), a shade cooler than what was measured on Airbnb (#EBEBEB).

Cost of switching: that line colour is used as one single value everywhere else in the app, so a one-screen exception breaks the "one colour, every divider" rule.

Cost of keeping it: this one line will never be a pixel-for-pixel match to the reference, though the actual difference is small.

3. Soften body text to Airbnb's ink, or keep Solen's own?

Solen's text is a near-black (#0A0A0A); Airbnb's measured ink is a slightly warmer dark grey (#222222).

Cost of softening: this colour is used for nearly every piece of text and the one main commit button across the whole site, so what looks like a one-screen question is really a sitewide decision.

Cost of keeping it: no accessibility rule forces either value, both read clearly, so there is no rule-based reason to move either way.

4. Which side margin actually wins: 20, 23, or 26px?

The account hub currently uses 20px of left/right margin. Airbnb measures 24pt, which is about 23px at our phone width. Solen's own separate written design notes already say 26px, on a different page. Three different numbers exist on paper and the account hub currently matches none of them.

Cost of picking any one: low, it is a small and safe change, but someone actually has to choose, because right now the shipped page is using a fourth number that nobody wrote down anywhere.

5. Standardize letter-spacing, or leave it alone?

Airbnb uses zero letter-spacing adjustment on every single piece of text in its system. The account hub currently renders four different letter-spacing values in one screen, and there is no written rule anywhere in this project covering letter-spacing at all.

Cost of standardizing: minor visual risk, but it is genuinely undecided work, not a broken rule, since no rule exists yet for this axis to check against.

Cost of leaving it: the inconsistency stays invisible to any written check, since nothing is currently watching this axis at all.
