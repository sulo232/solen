What actually changes. Two things, and only two. First, the icon-row header above the list gives back some of its own top and bottom padding, real chrome, same content. Second, one existing row, the June confirmation that already says "La Belle Ongle" in its own text, moves to the front of the list and grows from a 44px grey circle into a full-width photo using that salon's own real cover photo, fetched live, not a stock swap. The other three rows: same icons, same copy, same order relative to each other, untouched.
What this does not touch. The three rows that report a rejected salon application or a cancelled booking have no salon to show a photo of, they name no salon in their own text, so they keep their neutral icon rather than being given a fabricated one. And two numbers in the brief for this screen did not hold up under a live measurement: the heading reads 20px, not 28px, and the largest-to-body ratio measures 1.67x, not 1.87x. Both actually fail their floors. This mechanism does not fix either, that needs its own decision on the heading, named here so it is not lost.
The tradeoff worth a yes or no. Moving the June row to the top means the list is no longer in pure newest-first order, the July items now sit below a June one. That is the one real cost of "higher." The alternative is leaving it in place and only growing it, which keeps the order honest but does not move anything up, since it is already the last row. This file takes the "move it" option so the effect is visible and measurable; if you would rather keep strict recency order, this is the one line to say so.
