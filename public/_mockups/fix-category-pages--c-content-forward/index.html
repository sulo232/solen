One value here needs your yes specifically, because it moves a decision you already made

The card-width change (231px to 277px) widens SalonCard.tsx's mobile width formula from (100vw-44px)/1.5 to (100vw-44px)/1.25. That 1.5 value is not an accident: the code comment next to it names a dated decision, tagged R4-2, "owner 'V2, not V3': bigger card at ~250px with the next card peeking, was /2.2 ~167px", from July last year. You already chose bigger over smaller once. This mockup asks to go a step further in the same direction you picked, not the opposite direction, but it is still a step past an already-decided number, so it gets its own yes rather than a silent bump. The real cost: the next card's peek shrinks from showing 58% of the second card to showing 32% of it, still visibly cropped (the scroll promise holds), just a smaller tease. If shipped, this would use the width override the component already supports (widthClassName), scoped to the category rails only, not a change to the shared default every other SalonCard row uses.
