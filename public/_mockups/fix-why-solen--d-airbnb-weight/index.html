The honest catch: this screen's weight was not broken

Of the six numbers this page was graded on, weight share is the one that already passes. It reads 29.41% today, under the 30% ceiling, before this file touches anything. The three floors that actually fail here, no photo in the first screen, a heading 0.7px short of the 28px minimum, and eight type sizes with six crammed into one 8px band, are not size or weight the same way: font-weight cannot add a photo, grow a heading, or remove a size. This file still does its one job, and does it completely (weight share falls to 0%), it is just not the arm that fixes what is actually wrong with this screen.

Why this is the Airbnb mechanism and not a restyle

The owner named Airbnb as the source of truth on 2026-08-12. Measured that same month: Airbnb's own PDP runs about 3.1% of its text at weight 600 or heavier, seven elements out of 388, and carries its emphasis at weight 500 instead. This file does the same substitution here: nothing gets heavier than 500. Whatever used to stand out by being bold now has to stand out by being bigger or by colour, which is what the owner's own ladder says should carry hierarchy on every screen.

It is a real, working version of the fix, not a mockup of the idea: the change is a live script running against the real DOM, the same kind of script the other three variants of this page use to prove their own numbers.

What this does not touch. Weight and size are two different properties. Making text lighter does not make it bigger, add a photo, or reduce how many distinct sizes exist. The three floors this page actually fails, the 33% photo floor, the 28px anchor floor, and the 4-sizes-in-8px floor, are exactly where they were before. They are not this file's job and they do not move by accident here.
Checked, not assumed: no locked component collides here. The sibling weight fix on the Barbershop page ran into a real conflict, its walk-in row renders the real SalonCard component, and V3-D442 locks that card's name and price to weight 600. This page renders no SalonCard anywhere in its six sections: the bold elements here are the page's own heading, three section titles, a status word, and a badge count, none of them locked by weight in LOCKFILE.md. So nothing frozen is at stake on this specific screen. A sitewide version of this same script would still need every OTHER screen's locked elements checked the same way before running; this page's clean result does not clear that check for the rest of the site.
How this differs from the other three fixes being tried on this same page. One variant moves the size and spacing hierarchy. One variant adds real content. This one changes only which weight each element is allowed to carry. If this file's badges below show weight already passing and unchanged before and after on the other three numbers, that is not a partial result, it is the whole, honest scope of what a weight-only change can do on a screen whose weight was never the problem.
