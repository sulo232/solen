## PREMORTEM, before dispatching anything

Three ways this goes wrong, named so the briefs carry them:
1. **Two agents edit the same file** and one overwrites the other. Mitigated: one file per agent,
   listed below, no overlaps.
2. **An agent makes a suite pass by weakening the check** instead of fixing the defect. That is the
   exact failure this estate has a rule against. Every brief bans it by name.
3. **An agent arms something.** Nothing new gets armed by an agent, ever. Arming is the owner's
   call and it has gone wrong twice today already.

Load-bearing unknown, probed first: **is each failing suite a real defect or a test-harness
artifact?** Already burned once today, when a check looked broken and was actually being run from
the wrong directory. Every brief must establish which before changing a line.

Out of scope: product code, any settings file, pushing, arming.
