## What Codex must be careful about

The core fact to hold onto: right now, `approval_policy` is `never` and `sandbox_mode` is `danger-full-access`, and none of the 207 armed checks that exist today on the Claude Code side (see "Hooks" in the table above) are confirmed wired on the Codex side. Every "Codex side" note below that says "nothing" means exactly that: nothing stops this from happening except your own judgment, once, in the moment.

### Group 1: things that destroy

1. **Killing or rebuilding a shared dev or production server.** Never run `next build`, `next dev`, or `pkill` against a port another process is using; never `git stash`, `git checkout -- <file>`, or `git apply -R` in a shared worktree. Incident: 2026-09-05, a coder ran `rm -rf .next && npx next build` while a shared server and the owner's own production copy were both live; both went dark for twenty minutes. Default failure: any multi-step or background task run without being told a server is shared does this. Check: none is fully mechanical even in Claude Code; it is brief discipline, naming the exact commands and the exact cost.
2. **`git push`, `git stash`, `git checkout -- <file>`, `git reset`, force-push.** He pushes manually; pushing triggers a paid deploy. Incident: 2026-06-08, "i told u i dont want to push so many times." Default failure: `approval_policy: never` means nothing stops any of these from just running. Check: behavioral only, even in Claude Code.
3. **Dropping, resetting, or wiping the live Supabase database.** Never `supabase db push` / `db reset`; no DROP/TRUNCATE/ALTER-DROP/DISABLE-RLS/GRANT-TO-anon; no unscoped DELETE/UPDATE, whether through a tool call or a raw `psql`/shell command. Default failure: full filesystem and shell access with no approval step means a destructive SQL command, typed directly or copied from a plausible migration file, just executes. Check: Claude Code has two gates for this (MCP-tool and raw-shell versions); Codex side: nothing.
4. **Editing or deleting a file the task did not name; rewriting a whole file for a one-line fix.** "Surgical edits only": read before editing, match the exact scope, `git diff` after to confirm only the intended thing changed. Default failure: a "helpful" full-file rewrite ships a second, unrelated defect alongside the real fix, invisible until he finds it.
5. **Deleting a real route, page, or component with no graveyard entry.** Any deletion of a shipped surface needs a line in `_design-system/REMOVED.md` (keywords, what, why, the record) in the same commit, or the delete gets reversed. Default failure: the next session, Claude or Codex, does not know a deletion was deliberate and may resurrect exactly what was killed (a walk-in-card example was killed 2026-09-04 and proposed again 2026-09-04, rejected again on sight).
6. **Reading, printing, or leaking secrets.** Never open `.env.local`, `auth.json`, or any credential file; never print a secret; never put an API key in a URL query string; never store a raw booking or access token, only its hash; never leak the admin or service-role key to a client bundle. Default failure: full-access sandbox means Codex can open any credential file if asked, or while "helpfully" inspecting config during debugging.
7. **`--no-verify` on a commit, skipping hooks.** This also silently disables the graveyard check above, since that check runs as a commit hook.
8. **Proposing or building a new page, route, component, or migration without checking what already exists.** Run `npm run exists <keyword>` first; it searches routes, APIs, components, the database, and the graveyard (`_design-system/REMOVED.md`) together. ### Group 2: things that lie

1. **Fabricated numbers on a customer screen.** Never render a rating, price, count, distance, or status not wired to a live source; omit the element instead. Incident: 2026-07-16, "isnt ths maiking up fake sh a reccuring pattern," and it was, repeatedly, for weeks. Default failure: a plausible literal renders identically to a real one, and a model under pressure to "look done" reaches for a placeholder number by default.
2. **Fabricating identity or accessibility facts from a hash.** A 2026-07-26 migration set nine boolean columns (including wheelchair access and identity claims) from a hash function and called them all "cosmetic facets." The one real distinction: decorative facets (wifi, pet-friendly) may be seeded that way; identity, accessibility, or eligibility facts never may, every time, by name.
3. **Decoration: copy, a promised deadline, or a toggle that looks wired and is not.** A feature is not done when its pieces exist, only when the last one is connected. Measured 2026-08-19: 1,716 of 5,849 copy keys (29%) render on no screen; two were customer-facing promises ("you can report up to 14 days," "salon responds by {date}") shown nowhere, so a deadline was implied to nobody, enforced by nothing.
4. **Silent no-ops: a filter, column, or write that looks wired and discriminates nothing.** A filter must be proven to return a correct subset, not just render or return 200; a database write must be proven to hit a row, not just avoid throwing. This is this codebase's documented number one backend failure class (a day-key mismatch made an "open now" filter match nothing for weeks; an RLS write matched zero rows on every real booking while looking correct; a database view silently inherited its owner's RLS bypass and leaked every salon's booking rate to anonymous users).
5. **Claiming "done," "fixed," or "verified" without actually rendering or running it.** A passing typecheck or successful build is necessary, never sufficient. Incident: 2026-06-08, a dashboard was reported swept and screenshotted while the live dev server was throwing a global build error the whole time.
6. **Reporting a cause at a higher confidence than it was actually checked.** "Should," "presumably," "likely," "probably," "I believe" have no place in a claim about anything runnable, readable, or greppable in this repo. Either check it, or write "I did not check this" and why. A diagnosis is a claim too, and needs the same honesty.
7. **Treating a migration file, or an old audit's numbers, as current truth.** A migration file describes a replay, not the live database; an old audit is a snapshot, not a fact about today. This exact trap has independently produced at least four false "critical" findings in this project's history.

### Group 4: design law he will reject on sight

1. **Dark mode on the web app, in any form.** Web is one light theme, forever. It renders solid black on this app specifically; rejected twice by name.
2. **Blue used anywhere except small clickable accents.** Roughly 80% neutral surfaces, 17% ink; blue only on small tappable text, chips, or counts, never a big CTA, never a selected filter (selected is a neutral gray fill). ## How working here differs from Claude Code

The full 20-row researched comparison lives in `differences.md` (path below); the rows that change what you actually do day to day, plus what to use instead:

- **Permission model.** Claude Code has one named mode; Codex splits it into `sandbox_mode` times `approval_policy`, and there is no clean line-by-line mapping from an old allowlist. Port the intent (what should run unattended in this repo), not the rules.
- **The Workflow tool** (this repo's `council.workflow.js`, `prove.workflow.js`, `refine.workflow.js`) has no Codex equivalent. Use prompted subagent delegation for `council` and `prove` (spawn the four council-lens agents, tell Codex to merge their findings by file and line); `refine`'s round-counter and pass/fail loop is the strongest candidate for actually needing the Codex SDK, since a prose instruction cannot reliably reconstruct that control flow turn by turn.
- **The Browser pane** (`mcp__Claude_Browser__*`) has no confirmed native Codex equivalent. Use the repo's own Playwright scripts instead: `scripts/design/look-diff.mjs` (renders a route and prints computed values against reference measurements) and `scripts/_measure-guard.mjs`. Both were checked and have no hard dependency on Claude Code internals, so they move as-is.
- **`AskUserQuestion`** (a structured multiple-choice clarifier) has no officially confirmed Codex equivalent. Ask a plain numbered question in text, and always state a recommended default, per this project's own "lead with a recommendation" rule.
- **Preview links.** Give him a cloudflared tunnel URL, never a bare `localhost` or LAN IP link; his phone cannot resolve either. Never point the tunnel at a `next dev` server either, its build folder rewrites itself as you edit, and a cold phone-width load can render a black Next.js error screen set in the Geist font (Group 4 item 6's real cause). Build a real production copy (`next build` then `next start`) in the main checkout and tunnel that instead. Start the tunnel from a `launch.json`-equivalent entry (this worktree's `.claude/launch.json` already has the port and tunnel mappings; carry the same pattern over), confirm the tunnel actually connected before sending the link, and cold-check it (fresh browser context, not a warm session) before calling a visual turn done.
- **Worktrees.** Codex creates managed worktrees at `$CODEX_HOME/worktrees` (outside the repo) by default, not this project's in-repo `.claude/worktrees/<name>` convention. Look in the new place, or change the "Worktree root" setting if he wants the old layout back.
- **Hooks need per-edit trust.** Editing a hook changes its hash and Codex will ask to re-trust it; at least one open GitHub issue reports this trust prompt silently failing to appear at all on some versions. Never assume a hook "still works" just because it worked before an edit.
- **`AGENTS.md` silently truncates at 32 KiB by default**, with no warning shown. This project's rulebook is already over that cap; measured live tonight (`grep -bo`), the NEVER-AGAIN floors (byte 9,199) and the design contract (byte 27,327) both sit safely inside the cap, so a check that only asks about those would pass even while truncation is happening. What actually falls past byte 32,768 and gets silently dropped: Copy economy (byte 50,495), Surgical edits only (byte 64,943), and the Precedence chain itself (byte 68,949), which is exactly the section that says which rule wins when two disagree. Raise `project_doc_max_bytes` (see "Install order" step 4) before trusting that any of that is actually loaded.
- **Memory is a different kind of thing.** Claude Code's ~130 memory files are hand-written and durable by construction; Codex's Memories are auto-generated and explicitly not meant to be hand-edited. Anything that must always be true belongs in `AGENTS.md` text, not left hoping auto-memory reconstructs it.
