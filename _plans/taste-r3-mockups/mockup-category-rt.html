Category search route, map default & directory placement, two variants (English)

Mockup of the real category/search route (app/[locale]/[city]/[category]/page.tsx → SearchTemplate.tsx, the same template that renders /coiffeur, /barbershop, /nails, /spa, /search). Real result cards (SalonResultCard.tsx variant="feed"), real photos, real address strings. Two independent toggles below compare Current against Proposed, nothing here is built or committed.

Exists-check: npm run exists "category search route mockup" → 0 hits (net-new mockup file). salon_directory table exists live (48 rows, RLS on) with GET /api/directory already built, but no page currently renders it for customers (no frontend consumer yet). The "Also in Basel" placement below is the open design question, not a shipped feature. Map behavior (?map=1, mapOpen, the mobile FAB) is live in SearchTemplate.tsx, only the DESKTOP default (open/closed) is up for discussion here.

Map default (desktop)

Map starts CLOSED (Swiss cities are denser than Fresha's US/UK markets), the search bar's map icon and the "Show map" pill (real label: "Map") open it on demand. Map starts OPEN in a split: list left, map right, visible immediately, Fresha's default. The same pill now reads "List" and closes it back.

Directory entries (Google, not bookable)

A separate "Also in Basel" section BELOW the bookable results, clearly split off. Mixed directly INTO the results list, with a "Not bookable" tag on each card so it still reads as non-bookable.

Mobile (402px)

Map behavior on mobile is IDENTICAL in both variants (map starts closed, "Map" pill at the bottom), only the directory arrangement changes here. The desktop frame below demonstrates the map-default toggle instead.
