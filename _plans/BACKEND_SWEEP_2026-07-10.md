## Third ring , SECURITY DEFINER DB functions + deployed Edge Functions
- **28 SECURITY DEFINER functions swept , CLEAN.** The user-callable ones guard on auth.uid() (toggle_discovery_like/save RAISE 'unauthorized' if p_user_id != auth.uid(); current_user_tier self-only; set_customer_persona writes via auth.uid()). The money RPCs (redeem_voucher, redeem_user_credits, restore_*, decrement_retail_stock) are atomic + idempotent + capped-at-remaining (FOR UPDATE + ON CONFLICT DO NOTHING) , correctly written. NOTE: redeem_voucher / redeem_user_credits / restore_voucher / restore_user_credits have ZERO callers anywhere in the codebase , the atomic spend/restore RPCs were built but never wired. So voucher spend AND user-credit spend/restore are unbuilt (confirms the buy-only voucher finding + the 141-audit's "user_credits has no spend path"). Safe when wired; if wired, the restore-on-refund MUST be wired too or a refunded booking's voucher/credit is lost.
- **6 Edge Functions deployed + ACTIVE but scheduled by NOTHING (owner action).** post-booking-preferences, salon-verification, recurring-booking-processor, compute-analytics, booking-reminder, slot-auto-release are all live with verify_jwt=true (so invokable by anyone with the PUBLIC anon key) and each runs privileged SERVICE_ROLE logic internally, with NO in-code request-auth gate (zero 401/403 on a secret; booking-reminder is a bare Deno.serve). Nothing invokes them: pg_cron has only 2 SQL jobs, the GitHub Actions cron calls only /api/cron/* routes, and no code calls functions/v1. They are a DEPRECATED parallel implementation superseded by /api/cron/* (e.g. reminders now run via /api/cron/sms-reminders). => a dormant attack surface (anon-triggered reminder emails, slot releases, recurring-booking processing) with no current purpose. **Recommendation: DELETE the deployed functions** (`supabase functions delete <name>`, owner-gated destructive infra) after confirming no external scheduler relies on them; if any is still relied upon, add a shared-secret header gate + update its invoker in lockstep before it can be exposed. Not done autonomously (destructive deploy op + a small chance of an unseen external invoker).

## Recurring themes confirmed again (same as the 141-audit)

Second: service-role routes missing their own ownership check. The DB/RLS LAYER itself is now clean; the remaining risk lives in code that trusts client identity/amounts or reads drifted columns.
