## F. The thickness problem is an unenforced decision, not a missing one (2026-08-19)

Found by running the exists-check the gate demanded before letting me build the comparison sheet,
which is the check doing exactly its job.

- [x] **F1. An approved stroke system already exists.** `verified:` `lib/icon-stroke.ts`,
      `strokeForSize(px)`, table 14px to 1.6, 18 to 1.9, 22 to 2.2, 24 to 2.4. Owner-approved
      2026-07-16. It is monotonic ON PURPOSE: a bigger icon sits next to bigger text, and Inter's
      own stems thicken with size, so the icon must thicken too to read at the same weight.
- [x] **F2. Almost nothing uses it.** `verified:` `grep -rl "icon-stroke" app lib` returns FOUR
      importers: `app/[locale]/_components/layout/CategoryPillRow.tsx`,
      `app/[locale]/_components/layout/Header.tsx`,
      `app/[locale]/_components/search/FilterSheet.tsx`,
      `app/[locale]/queue/[token]/page.tsx`, plus `lib/icon-stroke.ts` itself.
- [x] **F3. The drift, measured.** `verified:` **ROOTS SCANNED, stated because an unstated root
      set is how the 2026-07-29 registry count came out wrong:** the whole worktree walked from its
      root, which covers `app/`, `lib/`, `components-legacy/` and every sibling directory, with
      four exclusions, `node_modules`, `.next`, `.git` and `public/_mockups`. Within that, files
      under `app/[locale]/dev/` are counted SEPARATELY because they are mockup routes and do not
      ship. Pattern matched: a JSX element that sets BOTH `size={n}` and `strokeWidth={n}`.
      Result on shipping code: **272 such icons, 254 of them (93%) disagree with the table**. The
      dev routes hold another 230 disagreements, excluded from that 93%.
- [x] **F4. The drift has a direction.** `verified:` sampled from the same scan, every size below
      the table's first step (14px, which maps to 1.6) comes out heavier, never lighter:
      `<Check>` at 9px uses 2.5; `<Clock>` at 10px in `FeaturedStylists.tsx` uses 2.5;
      `<Check>` at 10px in `ReportRefundEntry.tsx` uses 3.0; `<ChevronRight>` at 11px in
      `Reviews.tsx` uses 2.5; `<ArrowRight>` at 12px in `HeroDuo.tsx` uses 2.5. Not one small icon
      in the sample is thinner than approved, so this is one-directional, not scatter.

**What this does to the swap.** Importing a new icon set changes the shapes and leaves this
untouched, so the new set arrives just as uneven as the old one. The sequence is: apply the table
that already exists, THEN swap shapes. Doing it the other way round means doing the sweep twice.

**Honest state of the comparison sheet:** the Iconly artwork for 26 of our icons across all six
looks is harvested and the builder is written, but the sheet is NOT published yet. It was going to
say "pick one thickness", which F just proved is the wrong question, so it needs re-framing to
"pick one LOOK, the thickness is already decided" before it goes out.
